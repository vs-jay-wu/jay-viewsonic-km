VSFT-9208 · [Text] Flutter Text fallback Solution (pre-install)

Jira tickets 整合總覽 · clone 於 2026-07-16 · 對應 feature 資料夾 features/text-flutter-font-fallback-preinstall/ · Assignee: Jay Wu · Sprint 24（你說的都隊）· 8 pts
目前狀態：討論階段（尚未動 code）。 本 Story 僅涵蓋 Phase 1 — 預裝 20 套字體，從源頭減少需要 fallback 的情境。 Phase 2（fallback 機制）與 Phase 3（fallback 後跑版修正）不在範圍內。
一句話：外部 Google Slides / PPT 匯入 myViewBoard 時，若原始字體 App 沒有，Flutter 會 fallback 到別的字體， 因字寬 / 行高不同造成文字框被撐大、內容溢出。解法先把「生態系最常用的前 20 套字體」預先 bundle 進 App， 讓大多數檔案能以原字體或 metric-compatible 替代正常顯示。

3. Background（Spike 由來）

客戶 Rush–Henrietta Central School District 使用 Amplify 課程教材（Google Slides 格式），在 IFP52 匯入 myViewBoard 後，因字體不支援導致文字框被撐大、內容超出可視範圍，影響課堂體驗。

Spike VSFT-8753 定義了「不跑版」的驗收語意：

  • 版面不位移：文字位置與大小維持原樣，不撐大、不溢出、不擠壓周邊元素。
  • 內容完整：所有文字可見，不被裁切、遮擋。
  • 閱讀體驗一致：行數與換行位置盡量與原稿一致，避免大幅重排。

7. Windows 版做法（VSFT-9154 · Sparrow）

✅ 已查證（2026-07-16）：Windows 版在 edu-sparrow-app（C#/.NET UWP，MSIX 打包）， commit 2e6dddae7 [VSFT-9154] [Text] Windows Text fallback Solution (pre-install) (#277)，作者 William Lin。

做法（3 步）：

  1. 20 套字體 ttf 放進 src/Sparrow.Package/Assets/FontFamily/<Family>/。
  2. 在 Package.appxmanifest 用 <uap4:SharedFonts> 逐檔 <uap4:Font File="..."/> 註冊 → 安裝為 系統共享字體，Windows 文字引擎即可用「字體自己的 family 名」解析到。
  3. 有變體者用 variable font（Arimo / Gelasio / Inter / Merriweather / Montserrat / NotoSans / Nunito / OpenSans / Oswald / PlayfairDisplay / Raleway / Roboto…）， 其餘用靜態多檔（Caladea / Carlito / ComicRelief / Cousine / Lato / PTSans / Poppins / Tinos）。manifest 內確認為 20 套，與 ticket 一致。
兩個關鍵洞察：
  • 🔑 pre-install ≠ 字體對照。此 commit 只讓 20 套字體「用自己的名字可被查到」， 沒有做 Arial→Arimo 之類的映射。Sparrow 的「找不到字體→替換」是另一個獨立功能 （MissingFontDialog、PBI 95611「Font replacement / automatic regulation」）——對應本票的 Phase 2 / Phase 3，範圍外。
  • ⚠️ 踩雷 VSFT-9501：pre-install 後發現 Arimo / Open Sans 實際沒裝上系統，又補了一次 appxmanifest。 教訓 → 光宣告不夠，要驗證「裝完後引擎真的查得到該字體」，這會是本票的驗收重點。

8. Flutter 實作方向

範圍已收斂：只做 Phase 1 — 純 bundle 20 套字體，用正確 family 名可被解析； 不做任何原始字體名映射 / fallback（那是 Phase 2/3，範圍外）。

平台對照：

Windows (Sparrow)Flutter (本票 VSFT-9208)
註冊方式OS 系統字體（appxmanifest SharedFonts）❌ 不能註冊系統字體 → bundle 進 pubspec.yaml 的 fonts: assets（Q1 定案）
現況全 20 套新增repo 已內建 Roboto / Lato / Open Sans（3/20），機制現成
本票工作—沿用現有 fonts/ + pubspec 機制，補其餘 17 套，family 名正確即可
  • 骨架清楚：把缺的 17 套字體檔放進 fonts/，於 pubspec.yaml 依正確 family 名宣告；不動 OLF/匯入的 resolve 邏輯。
  • 離線：Q1 已定 bundle，不走 google_fonts runtime fetch（IFP 常無網路）——即使 pubspec 已有 google_fonts 套件，字體也要落地成 asset。
  • variable font：Flutter 支援，可壓縮字重檔案數；需確認 pubspec 宣告與 weight 對應正確。
  • 驗收（呼應 VSFT-9501 教訓）：bundle 後要實測「該 family 在 App 內真的解析得到、顯示正確」， 並用「使用已預裝字體的 Slides/PPT 樣本」匯入目視文字框不撐大。樣本可放 fixtures/。

字體選單（text editor font picker）差異

Sparrow 的選單「自動」有這 20 套；Flutter「不會」。 Sparrow 選單動態列舉系統字體（CanvasTextFormat.GetSystemFontFamilies() 減 HiddenFont 黑名單）， 預裝即出現、免改 code。Flutter 的選單是寫死清單 FONT_FAMILIES（lib/annotation_model/text_annotation.dart:69）+ flutter_quill patch google_text_style.dart 對照，bundle 不會自動進選單。

20 套 vs 現有 FONT_FAMILIES：

  • 已在選單（7） Roboto、open_sans、Lato、Montserrat、Poppins、Noto Sans、PT Sans
  • 不在選單（13） Arimo、Tinos、Cousine、Carlito、Caladea、Gelasio、Comic Relief、Oswald、Raleway、Nunito、Merriweather、Playfair Display、Inter
定案（Q7 = 選項 B）：20 套全部要在選單看得到，且全部 bundle 離線可用。 模型 = 20 套離線 bundled ＋ 其餘字體維持 google_fonts 動態下載。

google_fonts 共存分析（會不會衝突？）

結論：不會硬衝突，可共存。google_fonts: ^6.2.1 跑預設 runtime-fetch 模式 （無 GoogleFonts.config / allowRuntimeFetching 覆寫、無 google_fonts/ asset 目錄）：

  • google_fonts 不 ship 字體二進位（runtime 抓後快取）→ 我們用 pubspec fonts: bundle ttf 不重複、不撞名。
  • 命名空間不同：google_fonts 註冊改寫名（Montserrat_regular），pubspec 用字面名（Montserrat）。
  • 路由開關 = google_text_style.dart 的 _FONT_FAMILIES map：在 map → 走 google_fonts；不在 map → 走 bundled 字面名。

修正後範圍（3 個動作）

動作檔案對象 / 效果
① 加 ttf + 宣告 familyfonts/ + pubspec.yaml fonts:缺的 17 套（13 全新 + 4 目前走 google_fonts）落地成 asset → 離線
② 加進選單清單text_annotation.dart FONT_FAMILIES缺的 13 套加入 → 選單看得到（Q7=B）
③ 移出路由 mapgoogle_text_style.dart _FONT_FAMILIES4 套（Montserrat / Poppins / PT Sans / Noto Sans）移除 → 從 google_fonts 動態改成 bundled 離線

已 bundled 免動：Roboto / Lato / open_sans（3 套，本來就不在 map）。13 全新的字體不要加進 _FONT_FAMILIES map，維持 bundled。

明確排除（不在本票範圍）：字體選單「下拉預覽字樣」的離線化。 text_font_button.dart 的預覽對每個 item 無條件呼叫 GoogleFonts.getFont()， 這是 google_fonts 預覽機制的既有行為（現有 bundled 的 open_sans/Lato/Roboto 今天預覽就已 fallback）。 本票只保證套用 / 渲染離線正確；13 套新項目的「預覽字樣」離線時可能 fallback（選下去套用仍離線正確）， 與現狀一致，有意識地接受、不處理（要處理是另一張優化單）。
