[ClassSwift] MVB 內嵌 ClassSwift APK，停止從 OTA server 下載以縮短啟動時間

## Description

### 背景

目前 MVB 啟動後會從 OTA server 下載 ClassSwift apk 再安裝：讀 `version.json` → 下載約 15 MB → 安裝。第一次開機、網路慢或斷網時 ClassSwift 遲遲裝不起來，使用者點 Quiz Tool 就得等下載完成。

### 目標

ClassSwift apk 改為由 CI 在 build 時內嵌進 MVB 的 assets。MVB 裝好的當下就已經帶著對應版本的 ClassSwift，啟動後直接比對版號並在背景靜默安裝，全程不需網路。

### 範圍

**執行期（Flutter + Android）**

- 新增 `ClassSwiftInstallCoordinator`（取代 `ClassSwiftDownloadCoordinator`）：gating → 版號比對 → 解壓 → 靜默安裝，背景 fire-and-forget、不顯示任何 UI
- `ClassSwiftInstaller` 移除 `getDownloadUrl` / `_getLatestOtaVersion` / `_getOtaVersion`，版號比對改為「已安裝版號 vs 內嵌版號」
- 移除 `FileDownloader`、connectivity 監聽、斷網重試等整套下載機制；`VSUrls` 移除 `download_classswift*`
- 新增 Android `ClassSwiftAssetInstaller`：讀 `metadata.json`、背景執行緒串流解壓到 `getExternalFilesDir`，並以 `getPackageArchiveInfo` 驗證解出的 apk 與 metadata 相符（防 CI 埋錯 flavor）
- `ClassSwiftUpdatingDialog` 改為 coordinator 的觀察者，只在使用者於背景安裝完成前點 ClassSwift 時出現；此時才允許 silent install 失敗後 fallback 到 PackageInstaller
- Beta Program 不再另外下載 beta 版 ClassSwift —— beta 版 MVB 自己就帶著 beta 版 ClassSwift，安裝後啟動時自行安裝

**打包**

- apk 放在 `android/app/src/classswift/assets/classswift/`，透過 sourceSets 只掛給 `ifp` / `edla`；`open` / `store` 不受影響（Play Store 上傳的包不會多 15 MB）
- `androidResources { noCompress += 'apk' }`，避免二次壓縮

**CI/CD**

- `classswift_pin.json` 鎖定要內嵌的 ragdoll-cat release tag，apk 本身不進 repo
- 新增 composite action `embed-classswift-apk`：依 release target 選 flavor（stage→Stag / beta→Rc / production、rollback→Prod）→ 下載 release asset → 驗 sha256 → 放入 assets 並寫 `metadata.json`
- 接入 `stage` / `beta` / `production` / `rollback` / `daily-build` 五個 workflow
- 新增 `classswift-bump.yml`：每日檢查 ragdoll-cat 最新 release，較新則開 draft PR 更新 pin（開 PR 前確認該 release 具備 Stag / Rc / Prod 三種 Release APK）
- 本地開發用 `make fetch-classswift`

### 驗收條件

- IFP / EDLA build 的 APK 內含 ClassSwift apk；STORE / OPEN build 不含
- 裝置無網路時，MVB 首次啟動仍能完成 ClassSwift 安裝
- 已安裝版本不比內嵌版本舊時不重複安裝
- 背景安裝過程完全不顯示 UI、不彈出系統安裝畫面
- 背景安裝失敗後，使用者點 ClassSwift 會自動重試並允許系統安裝畫面

### 驗證紀錄

- 2761 個 unit / widget test 全數通過；`flutter analyze` 改動範圍內無 warning
- 實際 Gradle build 確認：`ifp` / `edla` 含 15 MB asset，`store` / `open` 不含
- `noCompress` 生效（打包後僅多 178 bytes，為 stored 而非 deflate）
- CI 下載 + sha256 驗證流程實跑通過

| D2 | 安裝時機與 UX | 啟動後背景靜默安裝；更新 dialog 只在使用者於安裝完成前點 ClassSwift 時出現 |
| D3 | apk 來源 | `classswift_pin.json` 鎖 tag，CI build 時下載並驗 sha256；apk 不進 repo |
| D4 | 版本 bump 交付方式 | 提供 commit / pr 兩種模式，排程預設 commit |
| D5 | Beta Program | 只下載 beta 版 MVB，不再另抓 beta ClassSwift |
| D6 | 與 MDM（MVB_QuizTool）派送並存 | **移除 MDM 派送**（ragdoll-cat `_deploy-mvb.yml`），不再需要 |

D9 曾評估 (a) ClassSwift 改 per-ABI 產出 + MVB 每個 ABI 各跑一次 build、(b) MVB 不再 split-per-abi、(c) 接受現況；採用 (c)。後果是 S3 儲存與裝置下載量會因每個 ABI 各背一份而上升。若日後體積成為問題，(a) 是效果最好的方向。

**Review 找到並已修正的問題**（票面 comment 列 B1–B7；PR 內 review 文件為完整版 B1–B17）

| # | 問題 | 影響 |
|---|---|---|
| B1 | 實際 APK 的 versionName 是 `1.6.3-stag` 而非 tag 的 `1.6.3`，原生端做嚴格字串比對 | 所有 stage / rc 版都會被拒裝 |
