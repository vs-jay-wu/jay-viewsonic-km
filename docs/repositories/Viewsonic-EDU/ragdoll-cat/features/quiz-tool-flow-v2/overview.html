0. 一句話

出題流程從「截圖 → Setting 頁 → 派題」改成「截圖（含設定）→ pre-start 作答窗 → Start question 才派題」。 題型與選項的設定搬進截圖遮罩上的 Question Panel，六個 MVB Setting 頁全部消失； 作答窗往前長出一個「還沒開始」的 pre-start 狀態，成為上傳與派送的唯一觸發點。

6. Review 抓到的缺陷

詳見 缺陷紀錄。這裡只列使用者可見的五個， 它們有一個共同形狀，見下一節。

症狀根因修在
pre-start 沒有班級時謊報「請檢查網路」 旗標算的是「網路 AND socket」，而 socket 是進課堂才連 #1137 → #1140
沒有班級時真的斷網反而不提示 上一個修法把 net 一起短路掉了 #1140
End class 之後拿不到取得班級的兩顆按鈕（整個 session） 判定同時依賴 flow 與「視窗是否存在」，後者不是 flow #1141
pre-start ✕ 關不掉視窗、跳錯誤 toast if/else 把新的 PRE_START 當成進行中，去關一個從未建立的題目 #1134
投影指示器不熄、MediaProjection 常駐（~100MB） 釋放規則綁在編輯窗 tag，而 capture 已改落在作答窗 #1145

7. 一再重演的形狀

「模組沒被改，但它依賴的前提被改了。」 這條分支上使用者可見的缺陷，多數不是誰寫錯，而是流程從某個模組底下換掉，而型別系統對此沒有意見。
案例沒被改的模組被抽掉的前提
capture session 洩漏 CaptureSessionReleasePolicy（自 VSFT-9013 起一行沒動） 「截圖後開的是編輯窗」
End class 後空狀態消失 PendingSelectClassState 「教室狀態發射時，視窗狀態已經是最終值」
pre-start ✕ 關不掉 showCloseConfirmDialog 的 if/else 「QuizState 只有結果頁與進行中兩種」

三個共通點：

  1. 編譯器不會擋。 if/else 不像 when 會因新列舉值而失效； tag 集合寫死常數不會因路由改變而失效。
  2. 失效是無聲的。 沒有 crash、沒有 log，只是某個狀態永遠停在錯的值。
  3. 既有測試擋不住，因為測試往往把那個帶著隱性依賴的判斷式 stub 掉了 （PendingSelectClassStateTest 注入 isTeacherInClass = String::isNotEmpty， 正好蓋掉真正的依賴）。

實務上的解法都一樣：把隱性輸入變成顯式的、可觀察的參數， 並在測試裡走一次真實的狀態轉換（而不是斷言靜止值 —— 那常常剛好等於初始值而假綠）。

9. 在這條分支上工作

9.1 切過來之後一定要做

./gradlew :app:mergeStagDebugResources --rerun-tasks

否則 processStagDebugResources 會拿殘留的合併資源去 link 已刪除的 dimen， 噴 resource dimen/... not found。切分支後改動 nav_graph.xml 的話， safe-args 產生碼也要 --rerun-tasks 重跑。

9.2 本機自己跑 gate（CI 不會幫你跑）

./gradlew compileStagDebugSources lintStagDebug testStagDebugUnitTest \
          compileStagDebugAndroidTestSources --continue

最後一項不在 CI 的清單裡，androidTest 源集曾因此靜默腐化過一段時間 （ActivationKoinTestRule／KoinIntegrationTestRule 的簽名漂移）。

9.3 rebase 的陷阱

這條 feature branch 被 force-push 過（rebase 到 develop）。 upstream 一旦重寫，git rebase origin/feature/quiz-tool-flow-v2 會因為 merge-base 退回 develop 分岔點而開始重播上游所有 commit（實測 21 檔衝突）。正解是明確指定舊基底： 
git rebase --onto origin/feature/quiz-tool-flow-v2 <你的舊基底 SHA>
先用 git merge-base --is-ancestor <舊 tip> origin/feature/quiz-tool-flow-v2 判斷是「純新增」還是「被重寫」。

9.4 fusion 建置與驗證

cd edu-droid-flutter/android
./gradlew :app:assembleEdlaDebug -PclassswiftRepoPath=<ragdoll-cat 路徑>
# APK 在 edu-droid-flutter/build/app/outputs/apk/edla/debug/（repo 根目錄的 build/，不在 android/ 下）

裝完先確認 overlay 權限：adb shell appops get com.viewsonic.droid SYSTEM_ALERT_WINDOW。 fusion 模式沒有任何地方檢查它，權限一掉就是完全靜默的失敗。
