## Panel 位置規則

**前提：Panel 為浮動元件，截圖框不主動位移。**

**A. 左右**（依序判斷，第一條成立就停）

1. `框右邊緣 + Panel 寬 + 24 ≤ 視窗寬` → 放**右側**，間距 24 px
2. `框左邊緣 − Panel 寬 − 24 ≥ 0` → 放**左側**，間距 24 px
3. 左右皆不符合 → **overlay 在框內，維持當前所在側**

**防抖動**：右→左門檻是 `< W+24`，左→右是 `> W+24+40` —— 兩個門檻**刻意不對稱**。

**B. 上下**（一律套用）：垂直對齊框中線，**碰到畫面上下緣就往回推**。允許壓在標題列／工具列上，但**不允許任何一部分落在畫面外**。

> A 組只改 x，沒有任何一條會動到 y。把面板拉出畫面的正是「對齊框中線」本身 —— B 不能省。

## Setting 頁已經被掏空一半

`Mvb*EditWindow`（spec 稱 Setting 頁）**不再派題**了。它現在只做一件事：把畫面推進到作答窗的新狀態 `QuizState.PRE_START`；真正的上傳與派送由作答窗那顆 Start question 觸發。

所以刪它的時候，刪的是一層薄殼，不是一條派題路徑。

## 但它還握著四件事，遮罩要接手

刪掉之前這四件必須有新家，否則會**靜默**壞掉：

**1. 截圖上傳的觸發（最容易漏）**

```kotlin
quizEditWindowModel.startUploadImage(screenshotManager.getScreenshotImageUri())
```

每個編輯窗有 3 個呼叫點：初次進入、上傳失敗重試、重新截圖。繪圖題不同，走 `windowModel.addPage(uri)`。**編輯窗一刪就沒有人上傳了。**

**2. 選項設定（只有 multiple choice / poll）**

派題需要選項數量與型別，但讀它們的元件在編輯窗上。我改成進 pre-start 的當下就寫進共用狀態：

```kotlin
QuizSharedUiInfo.quizOptionCount = binding.mvbOpOptionPanel.getOptionNumber()
QuizSharedUiInfo.quizOptionType = when (binding.mvbOpOptionPanel.getOptionValueType()) {
    OptionValueType.NUMBER -> QuizOptionType.NUMBER
    OptionValueType.ALPHABET -> QuizOptionType.ALPHABET
}
quizEditWindowModel.saveMultipleOptionInfos()
```

遮罩上會有同樣的控制項，**寫進同樣的欄位**即可，作答窗那側不用改。

**3. 重新截圖時要重設共用狀態**

```kotlin
QuizSharedUiInfo.screenshotImageUri = screenshotManager.getScreenshotImageUri()
QuizSharedUiInfo.setQuizTypeByTag(tag)
```

（首次進入是 `QuizMenuWindow` 設的，那條在遮罩前面、不受影響。）

**4. 進 pre-start 的交接**

```kotlin
quizManager.changeQuizState(QuizState.PRE_START)
csWindowManager.removeWindow(tag)
csWindowManager.createWindow(get(Mvb*StartWindow), Gravity.CENTER)
```

順序重要：`changeQuizState` 必須在 `createWindow` **之前** —— 作答窗在 `onCreate` 就會讀它決定要不要進 pre-start。

## 繪圖題：交接的是 model 實例，不是共用狀態

其他五個題型的草稿走 `QuizSharedUiInfo`，繪圖題目前不行 —— 它的草稿（含上傳後的 `dispatchUrl`）活在 `MvbSketchResponseEditWindowModel` 裡，而那個 model 在 Koin 是 `factory`，作答窗自己注入只會拿到全新的空實例。

所以編輯窗是把**實例本身**交過去，連生命週期所有權一起：

```kotlin
startWindow.initialSketchCount = windowModel.uiState.value.pageCount
startWindow.preStartEditModel = windowModel
hasHandedOffWindowModel = true   // onDestroy 要跳過 onCleared()，否則草稿的 scope 會被砍掉
```

遮罩取代 Setting 頁之後，這個交接要由遮罩那側做：誰持有 model，誰負責交出去並跳過自己的 cleanup。

若想讓繪圖題跟其他五個題型一致，作法是把「上傳後的 URL」也放進共用狀態、讓作答窗自己組派送內容 —— 那樣 `preStartEditModel` 這條就可以整個拿掉。細節在 commit `ce42bfa3` 的訊息裡。
