## Description

Scope 2。pre-start 右欄 0 學生時的空狀態，以及**什麼時候會自動彈出取得班級／Join Class 的視窗**。

**平台**：Windows（whiteboard mode 與 desktop mode 皆須涵蓋）

⚠️ 本票依 **Figma 流程圖**實作（子頁 3 有 12 個 node 對照）。尺寸／色值一律以 Figma 為準。

## 一、進場時要不要自動彈視窗

抵達 pre-start 的那一刻，依兩個問題決定：`In lesson?`（有沒有已進班的教室）與 `>=1 student joined?`。**只有一種情況會自動彈。**

| 有沒有教室 | 現場學生 | 自動出現的視窗 | 右欄顯示 |
|---|---|---|---|
| 有 | 1 位以上 | **沒有** | 學生名冊 |
| 有 | **0 位** | **join class 面板**（右側）自動出現 | 空狀態：**Waiting for students to join…** ／ Share the class link so your students can join. |
| **沒有** | — | **沒有** —— 不自動彈任何視窗 | 空狀態：**No students yet** ／ Start a one-time class, or pick one you’ve already made. ＋ **One-time class**／**My classes** 兩顆按鈕 |

「沒有教室」不自動彈，是因為此時老師還有一個系統替他決定不了的選擇（一次性班級 vs 既有班級）；自動彈出任一個都是替他做決定，而且他一關掉就沒有路走了。

## 二、兩顆按鈕觸發什麼

| 老師按 | 出現什麼 |
|---|---|
| **One-time class** | 直接起一次性班級，**join class 面板**出現（班級碼／QR）；右欄轉為「Waiting for students to join…」 |
| **My classes** | **選班卡**出現，內容依老師有沒有班級分兩種（見下） |

## 三、選班卡的兩種狀態（`my classes == 0?`）

| 狀態 | 清單區 | 主要行動 | 底部 |
|---|---|---|---|
| **一個班級都沒有** | Google Classroom icon ＋「Open myViewBoard Hub in your browser to import your Google Classroom roster.」 | **Open myViewBoard Hub**（實心主按鈕）。**沒有 Enter class** —— 沒有東西可以進 | 分隔線「Or」＋ **One-time class · Start now** |
| **有班級** | 班級清單（班名＋人數，預設選中第一個） | **Enter class**（實心主按鈕） | 同上 |

兩種狀態共通：卡片標題 **Quiz Tool**、organization 下拉（Default organization）、右上 **✕**、區段標題 **My classes**。**不論有沒有班級，一次性班級永遠是備援出口** —— 這是「按了 My classes 才發現自己沒有班」時不會走進死路的原因。

## 四、進班之後與學生加入之後

| 事件 | 畫面 |
|---|---|
| 選班卡按 **Enter class** | 進班完成後**換成 join class 面板**；右欄「Waiting for students to join…」。**不自動派題** |
| **第 1 位學生加入** | **join class 面板不自動關閉**、位置不動；右欄由空狀態轉為名冊；Start question 轉為可按 |

## 五、空狀態的視覺

icon ＋ 標題 ＋ 說明文字（＋按鈕，視變體而定）。**不使用骨架卡** —— 匿名骨架卡只留在「進行中」狀態。

> ⚠️ **文案刻意與 Figma 分歧**：設計稿寫的是 `No student yet`（單數），**實作與翻譯一律用** `No students yet`（複數）。這句會進 41 個語系，已定案以 spec 為準；需回頭請設計改稿。

## A. 已定案，但子頁 3 正文還是舊的

**1. 錯誤碼格式：**`Error 1001` → `CSW-<code>`
子頁 3 的 `S2-30a` 以 `Error 1001` 示意。本 repo 已有錯誤碼目錄 `MvbErrorCode`（single source of truth），顯示時前綴 `CSW-`。版面照設計稿（括號包住、獨立一行），只有碼本身換成既有慣例，例：`(CSW-1001)`。已與 Jessi 確認採 repo 慣例。

**2. 兩個錯誤態的 node-id 已取得，對照表待回填**
子頁 3「Figma node 對照」最後一行仍寫「設計稿已提供圖檔，尚未取得 node-id」。實際是：

- 斷網態 `22663:70955`
- API／token 失敗態 `22660:40042`

兩者皆為 `instance`、500×680、貼齊父層右緣（1420 + 500 = 1920），與 spec 說的「置右」一致。

**3. 「三顆按鈕」需要寫明是哪三顆**
`S2-30`「toggle、三顆按鈕與題目草稿都不受影響」與 `S2-30c`「可從三顆按鈕再試一次」，但 pre-start 右欄只有 One-time class／My classes **兩顆**，容易誤讀。已確認三顆是指 **mVB toolbar 的 **`myClass`／`quiz`／`collection`，與右欄那兩顆是不同的東西。

因此 `S2-30c` 的重試其實有**兩條並存路徑**：右欄兩顆、以及 toolbar 三顆。建議正文寫明，否則實作只會做其中一條。

**4. 班級畫面 ✕ 的雙語意只在留言，未進正文**
Jessi 先前留言：「按下 joinClass 面板的 close button，如果還沒加入班級的話就是關閉面板，如果有班級就是 End Lesson」。這條沒有進 spec 正文。

補充適用範圍：它只作用在**班級畫面真的會出現**的入口（mVB toolbar 的 Join Class 按鈕、pre-start 的取得教室）。mVB 直接派題那條路不經 pre-start，且該路徑本來就不顯示班級畫面，天然在範圍外。

**5. 學生數口徑：「現場學生數」→「已具名學生數」**
`S2-4`／`S1-6` 寫「現場學生數為 0」。實作口徑是**已具名**（學生 `LoginStatus == NameSet`）——已選座位但姓名尚未送出（名單顯示 Typing…）的學生不計入。差別是真的會踩到：讀「現場」的話學生一點到座位 Start 就亮了，派出去會在結果頁留下永遠空白的一格。建議正文改用「已具名」。

**6. 斷網文案的結尾符號不一致**
子頁 3 正文寫 `No internet. Reconnecting…`（省略號），設計稿是 `No internet. Reconnecting...`（三個半形句點）。既有 i18n key `mvb_join_class_no_internet_reconnecting` 的實際值我們還沒核對。三者需擇一，否則翻譯會分岔。

## C. 給後續讀對照表的人的提醒

**11. node-id 有內外兩層，引用要選對**
同一個畫面在 Figma 存在兩個層級的 id。子頁 3 對照表記的是**外層 1920×1080 整機畫面**（frame 名稱多為 `Open File`），而溝通時常貼的是**內層面板**：

| 畫面 | 外層（對照表用的） | 內層面板 |
|---|---|---|
| 沒有教室 | `22278:85926` | `22288:86458` |
| 有教室＋0 學生 | `22291:90938` | `22291:90943` |
| 有教室＋有學生 | `22291:90511` | `22291:90516` |

兩層都要留：**跨視窗互動看外層，版面間距抓內層**。特別注意 join class 面板（`22291:91705`）是內層作答頁的**兄弟不是子孫** —— 只看 `22291:90943` 的截圖，右側根本沒有 join class 視窗，而「自動出現」正是這格的重點行為。

另外，兩個錯誤態的圖層名都叫 `my class menu`（沿用選班卡元件沒改名），與畫面內容無關，且兩者 metadata 完全相同、只有 variant override 不同 —— **無法靠圖層名或 metadata 分辨，只能靠截圖**。
