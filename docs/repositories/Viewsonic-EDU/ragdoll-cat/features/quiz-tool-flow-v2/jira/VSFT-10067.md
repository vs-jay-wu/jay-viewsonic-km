## Description

Scope 2。**Setting 頁移除**，作答頁往前延伸出一個派題前的 **pre-start 狀態**。

**平台**：Android

## 一句話

**pre-start 就是進行中的畫面，只是還沒開始。**

## 版面：與進行中完全一致

| 元素 | pre-start | 派題後（進行中） |
|---|---|---|
| 題型摘要 chip | 顯示 | 相同 |
| **題目縮圖** | **顯示** | 相同 |
| **Options 選項卡** | **顯示** | 相同 |
| 右欄 Responses 標頭、Refresh、計數 | 顯示，計數 0 / 0 | 相同，隨作答更新 |
| **計時器** | 顯示，**00:00 未起跑** | 相同位置，**開始計時** |
| **右欄內容** | 0 人時**空狀態**；有人時名冊 | 學生名冊 |
| **主要按鈕** | **Start question** | **Stop submissions** |

**只有三處不同**：主要按鈕、計時器是否走動、右欄是空狀態或名冊。**不得為 pre-start 另做版面或隱藏任何既有元素。**

> ⚠️ 這推翻了先前 POC 的做法（大碼錶取代題目縮圖、移除 Options 與 header 計時器）—— 該做法**已作廢**（子頁 4 決策 #27 反轉）。票名裡的「碼錶」指的是**同一個計時器停在 00:00**，不是換版面。

## Start question 是唯一的觸發點

| 時機 | 發生什麼 |
|---|---|
| Capture 完成 | 題目草稿成形，畫面前進到 pre-start。**不上傳圖片、不建立題目** |
| 按 Start question | **這一刻才**依序執行圖片上傳 → 題目送出 |

按下後主要按鈕內 loading、期間不可重複點；失敗留在原畫面＋toast，草稿完整可重試。

## 主要按鈕：兩種語意，只有一邊有條件

| 狀態 | 按鈕 | 可用性 |
|---|---|---|
| pre-start | **Start question** | **沒有學生加入前反灰**（不論有無教室）—— Scope 1 的「無教室例外放行」**取消** |
| 進行中 | **Stop submissions** | **恆可按**，不看學生數、不看是否曾有學生、不看有無作答資料 |

Start 設條件是因為它會產生一份沒有人作答的結果；Stop 是「結束」不是「送出」，擋住只會把老師鎖在他想離開的狀態裡。

## 其他行為

## `13` 不是「還沒做」，是壞的

`showCloseConfirmDialog()` 只分兩種狀態 —— 結果頁與「其他」。`PRE_START` 是本票新增的第七個狀態，掉進「其他」後被當成一場進行中的測驗：

1. 文案是「Unfinished responses will be lost」，但 pre-start 一個 response 都不存在
2. 確認後打 `PUT /api/v3/quizzes/:quiz_id` 去關一個**從未被建立**的題目（`7`：pre-start 不上傳、不建立題目，所以 quizId 是空字串）。請求沒有 id，實際送出的是 `PUT /api/v3/quizzes/`，後端不認，老師拿到錯誤 toast 而且**視窗關不掉**

**實機確認（2026-09-01）**：連著網路時 pre-start 的視窗無法關閉。斷網反而關得掉 —— 那條分支走本地關窗、不打 API。

修法是在既有邏輯前面加一段短路，不碰進行中與結果頁的關窗路徑。丟棄動作與既有的「離線就地關窗」做同樣三件事：清 quiz info、關窗、收任務。

## 實際原因

那個測試的兩個 mock 餵了互相矛盾的狀態：

- `QuizStartWindowModel.quizzingUiState` → `QUIZ_RESULTS` ＋ 兩位學生的作答
- `QuizManager.quizzingUiState` → 裸的預設值（等於 `QUIZZING`）

視窗判斷版面狀態讀的是 **QuizManager**，於是它以為還在進行中，結果頁的高亮與計數就沒有被套上 —— 畫面看起來像「高亮功能壞了」，其實只是餵錯狀態。

`QuizManager` 那個 stub 是我在 pre-start 那批（`32fd4f31`）加的：當時六個作答窗開始在 `onViewCreated` 讀 `quizManager.quizzingUiState`，relaxed mock 的 `StateFlow.value` 會回傳裸 Object 而讓九個測試檔爆掉，我一律補上預設值，沒有逐檔確認那一檔原本想測的是哪個狀態。

## 影響範圍

同樣「兩邊狀態不一致」的情況還在另外三個檔案（它們對 `QuizStartWindowModel` 餵的是 `QUIZ_RESULTS`，但 `QuizManager` 是預設值）：
