環境準備 
open -n ~/.mvb-dd/poc-desktop-mode/Build/Products/Debug/myViewBoard.app
進入點：主工具列最右邊那顆「螢幕」圖示。

擷取那一區（§C）需要「螢幕錄製」權限；沒授權時原型會跳系統設定並顯示提示， 授權後要重開 app。

A. 核心流程

最重要的一區
進入模式：工具列出現在滑鼠所在螢幕的底部中央A1
  1. 把滑鼠放在某一個螢幕上，點主工具列的「螢幕」鈕。
期望：白板主視窗消失，桌面照舊，浮動工具列出現在滑鼠所在的那個螢幕底部中央。
五支工具各畫一筆A2
  • 標記筆：不透明實線。
  • 螢光筆：半透明、疊在內容上仍看得見底下的東西。
  • 雷射筆：畫的時候筆頭有光暈；放開後約 0.5 秒，線從「筆頭那端」開始消失（不是整條一起淡出）。
  • 橡皮擦：碰到就整筆刪掉，不是刮掉一小段。游標處有一個圈。
  • 游標：見 A3。
陷阱：雷射筆是「從頭開始擦」（對齊 Sparrow SmoothEraseFromHead）。如果看到的是整條同時變淡，那就是做錯了。
游標工具：桌面能正常操作，而筆跡還留在畫面上A3 · 新增行為
  1. 先用標記筆畫幾筆。
  2. 切到「游標」工具。
  3. 去點 Dock、拖動別的視窗、按其他 app 的按鈕。
期望：底下的桌面完全可以操作，而剛才畫的筆跡仍然浮在上面。
這是 Windows 版沒有的行為，要決定要不要保留 —— 是這次最值得跟 PM 討論的一點。
調色盤：換色 / 粗細 / 透明度，且每支筆各自記住A4
  1. 選標記筆 → 調成藍色、很粗。
  2. 切到螢光筆 → 調成綠色。
  3. 切回標記筆。
期望：標記筆回到「藍色、很粗」，不是繼承螢光筆的綠色。（對齊 Sparrow 的三組獨立 InkAttributes）
Undo / Redo / 清除全部A5
  1. 畫三筆 → Undo 兩次 → Redo 一次 → 清除全部。
  2. 再 Undo 一次。
期望：「清除全部」可以被 Undo 救回來；雷射筆的筆劃不該出現在 undo 歷史裡。
回白板：白板恢復、筆跡清空A6
  1. 畫幾筆後按工具列最右的「回白板」。
  2. 再進一次桌面模式。
期望：白板視窗回來且內容完好；再進去時是乾淨的（對齊 Sparrow：它的 DesktopMode 程序關掉筆跡就沒了）。
若你覺得「筆跡應該留著下次再回來」，那是產品決策，記下來 —— 目前刻意對齊舊版。
底下正在播的影片會不會被打斷A7 · 需要決策
  1. 別的 app 的影片：用 Safari／QuickTime 播一段影片 → 進入桌面標註模式 → 看它有沒有繼續播。
  2. 白板自己的影片：在白板頁面放一個 YouTube widget／影片物件並播放 → 進入桌面標註模式 → 回白板看它是否還在播、播到哪。
  3. 再用「不隱藏白板」的模式比一次： 
    open -n --env MVB_POC_KEEP_BOARD=1 \
  ~/.mvb-dd/poc-desktop-mode/Build/Products/Debug/myViewBoard.app
預期：別的 app 的影片會繼續播（我們只是疊一個視窗上去，從不跟它溝通； 失去鍵盤焦點不會使播放停止）。
白板自己的影片有風險。進入模式時主視窗被 orderOut，視窗變成 occluded， macOS 會節流被遮蔽視窗的計時器與媒體（WebKit 尤其明顯）。 這是我的設計選擇造成的，不是平台限制 —— MVB_POC_KEEP_BOARD=1 可改成不隱藏白板。 請比較兩種，決定要哪一種行為。
另外：DRM 內容（FairPlay／HDCP）覆蓋沒問題，但擷取時會變黑，那是系統保護，不該繞。

app 在前景時
1–5 切工具B1

⌘Z / ⇧⌘Z / ⌘⌫ / EscB2

⚠️ 穿透模式下快捷鍵會失效 —— 確認你能接受B3 · 需要決策
  1. 切到游標工具。
  2. 去點一下別的 app（例如 Finder）。
  3. 按 Esc。

C. 擷取三式

需要螢幕錄製權限
整個螢幕 → 落到白板目前頁C1
  1. 畫幾筆 → 工具列相機鈕 → 「整個螢幕」。
  2. 回白板看目前頁。
期望：圖已經放在白板上；標註有入鏡、工具列沒入鏡。
矩形選取C2
  1. 相機鈕 → 「矩形選取」→ 拖出一塊 → 放開。
  2. 中途按 Esc 試一次取消。
期望：只有框內的內容被擷取；Esc 能取消且不會留下半途的遮罩。
自由形狀 —— 遮罩要照著你畫的形狀切C3
  1. 相機鈕 → 「自由形狀」→ 畫一個明顯不規則的圈。
期望：放到白板上的圖是照著你畫的輪廓切的（外面透明），不是切成一個方形。
權限被拒時的行為C4
  1. （可選）在系統設定把 myViewBoard 的螢幕錄製關掉後重開 app，再試擷取。
期望：工具列上出現提示文字要求授權，不是無聲失敗、也不是當掉。

D. 多螢幕

你有三台，正好
三個螢幕都能畫（含「換螢幕的第一筆」）D1
  1. 三個螢幕各畫一筆。
  2. 在 A 螢幕畫完直接到 B 螢幕畫（不要先點工具列）——這條路徑以前會吃掉一筆。
  3. 跨螢幕拖一筆過去，線要連續。
舊行為：只有持有焦點的那一層收得到筆畫，其他螢幕的第一下被 AppKit 當成「activate」吃掉 （已用 acceptsFirstMouse 修）。若某螢幕仍完全畫不了，先確認 那個螢幕上是不是有別的 app 在 native 全螢幕（見 §E2）。
工具列：拖到別台螢幕、靠邊吸附成直式、再拖回來D2
  1. 抓工具列最左邊的握把（≡）拖動。
  2. 拖到螢幕左／右邊緣放開。
  3. 再拖回中間。
期望：靠邊會貼齊並轉成直排（對齊 Sparrow 的 ProcessDocking）；拖回中間變回橫排。
拖曳曾經有「越拖越快、飛出螢幕」的 bug（DragGesture.translation 是累積值），已修 —— 請確認拖起來是 1:1 跟手。
改顯示器排列後，筆跡要黏在原本的位置D3
  1. 在兩個螢幕上各畫幾筆。
  2. 系統設定 → 顯示器 → 把兩台的相對位置對調。
期望：筆跡仍在原本畫的那個螢幕的那個位置（筆跡存的是全域座標）。

E. Space / 全螢幕

macOS 最容易翻船的地方
切到另一個 Space，標註層還在嗎E1
  1. 進入模式並畫幾筆。
  2. ⌃→ 切到另一個 Space。
期望：標註層與工具列跟著過去（.canJoinAllSpaces + .stationary）。
⛔️ 別的 app 進 native 全螢幕 → 蓋不上去（已實測，做不到）E2 · 已有結論

這項已經驗過了，答案是做不到。實測（三螢幕，主顯示器上跑著 native 全螢幕的 app）： 三層 overlay 都建立成功，但該螢幕那層 onscreen=false、 一次 mouseDown 都沒收到；把 window level 拉到 CGShieldingWindowLevel() 也一樣。詳見 總覽 §5.1。

剩下的是對照實驗，麻煩你做：把那個 app 退出全螢幕 （同一個螢幕、視窗最大化就好），再試同一個螢幕能不能畫。
  • 能畫 → 結論確立：限制來自「別人的全螢幕 Space」。
  • 仍不能畫 → 另有原因，要重查（請把診斷檔給我）。
我們自己的白板進全螢幕則不受影響，標註層蓋得上去（已修正並驗過）。
Mission Control 打開時的樣子E3
不預期有正確答案，看一下會不會出現奇怪的殘影或把 Mission Control 蓋住。
