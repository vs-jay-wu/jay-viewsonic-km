Manager 本機開發與磁碟空間

實測於 2026-09-22 · 機器：Jay 的 macOS（內建 APFS ＋ Crucial X9 外接） · 用途：決定要不要／怎麼在本機跑 Manager 前後端
📘 總覽 (overview) 💾 本機開發與空間

結論（先看這個）

1. repo 不是問題。26 個 Manager repo 的真實內容總共 1.1 GB （31,280 個檔案）。全部放本機完全不需要考慮。
2. 「把 build／docker 放外接」這個方向，在這顆硬碟上不成立 ——它是 exFAT：不支援 hardlink、cluster 256K（小檔膨脹 18 倍）、小檔寫入慢 13 倍。
3. 該回收的是 Colima：它已經佔掉本機 14 GB，而且那是現在就能拿回來的。

1. repo 到底多大——外接上的數字是假的

du -sh 在外接硬碟上報的數字嚴重灌水，因為 exFAT 的 allocation cluster 是 256 KB（APFS 是 4 KB）。一個 1-byte 的檔案在外接佔 256 KB。

看 edu-dm-api-nestjs 那列：真實 18 M，exFAT 上佔 1,038 M——58 倍。 原因是它有 4,147 個檔案，而且大多很小。
⚠️ 不要用外接上的 du 數字規劃本機空間，會高估一個數量級。 我第一輪就是這樣報出「edu-dm-dashboard 2.7 G」的——那個數字對本機完全不適用。

另外：這些 checkout 都沒有 node_modules（實測 find 掃不到任何一個）， 所以上表不含依賴。

4. 「repo 本機、build/docker 外接」可行嗎

拆成三個不同的東西回答，因為它們的答案不一樣：

4.1 node_modules ／ build 產物 → 不建議

三個理由疊加：hardlink 不支援（pnpm 直接壞）、膨脹 （搬過去反而更耗空間，只是耗在外接）、小檔慢 13 倍 （npm install 與 webpack／Angular build 都是大量小檔 I/O，正是最痛的存取模式）。

實算（2026-09-24，edu-dm-dashboard 裝好之後逐檔量）： 
node_modules 真實內容        1.4 G   （185,034 個檔）
  → 本機 APFS（4K cluster）  1.9 G
  → 外接 exFAT（256K）      45.8 G   ← 23.7 倍
光這一個 repo 就會吃掉外接 46 G。原因是檔案又多又小， 每個至少佔一個 256K cluster。本機只要 1.9 G，而且快 13 倍。

pnpm 那條對 edu-dm-api-nestjs 與 edu-dm-iot-nestjs 成立 （它們的 postinstall 是 pnpm husky init）； edu-dm-dashboard 用的是 yarn 4 nodeLinker: node-modules， 不靠 hardlink，技術上放得上去——只是上面那 46 G 與 13 倍讓它沒有意義。

4.2 Docker／Colima 的 VM disk → 不要直接搬

Colima 的 datadisk 實測是：

~/.colima/_lima/_disks/colima/datadisk
  apparent: 100G   ← 宣告大小
  actual  :  14G   ← 實際佔用（sparse）
exFAT 不支援 sparse file，所以把它搬過去會從實佔 14 G 變成實佔 100 G。 而且外接只剩 505 G、沒有 TRIM 回收，寫入還更慢。這是反效果。

4.3 冷資料（不常用的 repo、image tar、備份）→ 適合

外接硬碟現在的用途（offloaded repo）本來就是對的：冷資料、整包存取、不做小檔隨機 I/O。 exFAT 的缺點在這個模式下都不痛。

5. 真要搬：APFS sparsebundle

如果之後真的需要把熱資料放外接（例如同時開多個大型 monorepo）， 正解是在外接硬碟上建一個 APFS 稀疏磁碟映像，掛載後就是一個正常的 APFS 卷宗。 已實測可行：

hdiutil create -size 200g -type SPARSEBUNDLE -fs "APFS" \
  -volname DevVol "/Volumes/Crucial X9/dev.sparsebundle"
hdiutil attach "/Volumes/Crucial X9/dev.sparsebundle" -nobrowse
能力exFAT 直接放APFS sparsebundle
hardlink不行可以
sparse file不支援支援（500 M 宣告＝實佔 0 B）
小檔寫入（300 檔）0.261 s0.020 s（與本機同級）
實際佔用—宣告 2 G 的映像，建立後實佔 28 M（隨用量長）
大小寫敏感否否（預設；要敏感得用 Case-sensitive APFS）
代價，先想清楚再用：
  • 硬碟沒掛載時，裡面的東西整個消失——路徑還在但目錄是空的， 而且不會有明確錯誤（同 Colima 的 $HOME 掛載陷阱）
  • sparsebundle 只會長大不會自己縮，要 hdiutil compact 回收
  • 拔硬碟前沒 detach ＝ 檔案系統層級的損壞風險，比 exFAT 直接放檔嚴重
我沒有實測把 Colima 的 datadisk 搬進 sparsebundle——上表只驗到 「sparsebundle 本身支援 hardlink／sparse／速度正常」。真要做要另外驗一次 Colima 起得來。

6. 先回收 Colima 的 14G

這是現在就能拿回來的空間，而且不影響任何 Manager 的工作。 Colima 目前是停的（colima is not running），那 14 G 是躺著的舊資料。

# 先看裡面有什麼（要先啟動）
colima start && unset DOCKER_HOST
docker system df

# 溫和：清掉沒在用的 image／build cache／volume
docker system prune -a --volumes

# 激烈：整個 VM 砍掉重建，順便把 disk 宣告調小
colima delete
colima start --disk 60 --cpu 4 --memory 8
⚠️ colima delete 會刪掉所有 image、container 與 volume。 確認沒有只存在本機、沒 push 過的 image 再做。
⚠️ colima start 之後一律 unset DOCKER_HOST ——它只會印 warning，然後你所有指令連到錯的地方。見 colima skill。
另一個跟 Manager 直接相關的 Colima 限制：Lima 預設只掛載 $HOME。 /Volumes/*（外接硬碟）與 /private/tmp 在容器內看不到， 症狀是空目錄或 No such file or directory，不會說「路徑沒掛載」。
→ 所以就算把 repo 放外接，docker compose 也 bind mount 不到它。 這條單獨就否定了「repo 放外接跑 docker」。

步驟

python3 scripts/repo-storage.py restore edu-dm-dashboard --org Viewsonic-EDU

cd .../edu-dm-dashboard
nvm install          # .nvmrc = 24.3.0（engines 要求 node >=24）

yarn install
yarn start:dm:stage  # → http://localhost:3000/mydashboard/dm

三個踩過的坑

① OIDC 的 redirect_uri 白名單只認 localhost:3000。
oidc.config.ts 的 redirectUri 是 ${window.location.origin}/mydashboard/dm/entity，跟著實際 port 跑。 所以換 port 會直接登不進去： 
# 實測 auth.stage.myviewboard.com/oidc/v1/auth
redirect_uri = localhost:3002  →  400 ERROR
redirect_uri = localhost:3000  →  302 導向登入頁 ✓
必須用 port 3000（也是 project.json 的預設）。 km web 的 dev server 預設也在 3000，兩者只能擇一。
② src/assets/i18n 是 gitignored 的產生物，缺了會直接中止。
generate-i18n-hash.js 會 ENOENT，而它跑在 ng serve 之前， 所以整個 start script 掛掉，錯誤訊息看起來跟 Angular 無關。
正規來源是 POEditor（yarn i18n:updateAll:dm，要 token）。 更省的辦法：直接從 edu-dm-dashboard-lang 的 latest/ 複製——那個 repo 的用途正是這份快照。 
find <lang-repo>/latest -maxdepth 1 -name '*.json' ! -name '._*' \
  -exec cp {} projects/device-management/src/assets/i18n/ \;
rm -f projects/device-management/src/assets/i18n/_manifest.json
⚠️ 兩個細節：排除 ._*（exFAT 上的 AppleDouble 檔，hash 腳本的 .endsWith('.json') 會把它們算進去），以及移掉 _manifest.json （那是 lang repo 自己的 metadata，原始 assets/i18n 沒有這個檔）。
③ edu-dm-dashboard-mobile 的 npm 版本是硬擋的。
它的 preinstall（check-npm-version.mjs）要求 npm 剛好等於 11.11.1（!== 就 exit 1）， 而 Node 24.3.0 自帶的是 11.4.2。要先把 npm 換成指定版本才裝得動。

還沒解決的

proxy.conf.json 把 /api/dm/v2/* 代理到 http://localhost:3001（假設本機有後端）。stage 設定用的是絕對網址， 實測確認 bundle 裡只有 stage 端點、沒有 dev／production 端點， 所以一般情況不會走到那條 proxy。但若有頁面用相對路徑打 API，就會撞上 ——真遇到再起 edu-software-manager-api（無 DB，只要三個設定指向 stage）。
