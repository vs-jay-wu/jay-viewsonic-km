6. ⚠️ Round-trip 風險：mvbf 存檔會洗掉 attribution key 必須處理

2026-07-30 更新：hardcode 新方向（§0）下 .olf 內沒有 attribution key，此風險整段消失——標註由偵測 category 動態顯示，存檔不影響。惟 category 本身屬白名單欄位、round-trip 會保留，方向定案前先保留本節備查。
  • mvbf 存 .olf 時（FileOLFSaveHelper → PageActivity.toOlfJson → HtmlActivity.toJson/toOlfJson）是白名單重建 JSON：只寫出已知欄位（id/x/y/width/height/matrix/category/source），未知欄位一律丟棄。
  • 後果：老師在 mvbf 開啟 Hub 派來的 .olf → 寫筆記 → 存檔，attribution key 就從副本裡消失，之後再播放（mvbf 或轉給 mvbw）都不再顯示標註 → 合規閉環被 app 自己打破。
  • 解法方向：HtmlActivity 解析時保留 attribution 原始 JSON（或未知欄位 pass-through），toJson/toOlfJson 時原樣寫回。這點票上 AC 沒有明寫，建議補進票或至少在實作 PR 內涵蓋 + 測 round-trip。
